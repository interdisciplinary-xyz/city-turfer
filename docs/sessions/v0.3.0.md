## Monorepo design

Full record: `docs/decisions/monorepo-turborepo-2026-10-18.md`. Decided:

- **Landing page goal:** static showcase only (what CityTurfer is, how turf works, screenshots,
  "coming soon"). No data collection, so no backend and no GDPR surface.
- **Web stack:** Next.js on Vercel. Static pages now; a waitlist or API routes can come later.
- **Package manager:** pnpm (replaces npm 10 + `legacy-peer-deps`).
- **Shared packages from day one:** `packages/brand` (colour tokens including the turf strength
  ramp, SVG mark and wordmark, tagline copy) and `packages/config` (tsconfig, ESLint, Prettier
  bases).

Known impact to plan for:

- Moving the app to `apps/mobile` and changing how `node_modules` is laid out will likely change the
  runtime fingerprint, so one native reinstall on the device is part of the move (pin `app.json` to
  `0.3.0` in the same step).
- pnpm with Expo: re-verify native autolinking, the MapLibre local SPM package
  (`plugins/with-local-maplibre`, `vendor/maplibre-spm`) and the local `modules/background-session`
  module with a fresh dev build.
- Root tooling assumes today's paths: CI, husky hooks, lint-staged, dependency-cruiser, Jest,
  `audit:docs`, `audit:logs`, `e2e:audit`, `check:secret-files`, EAS/OTA commands and the release
  workflow (`commit-and-tag-version`).

- **Layout:** `apps/mobile` takes the app with `e2e/` and the mobile-only tools; repo-wide tools
  (docs audit, secret guard, log audit, release) and `docs/` stay at the root. One version, one tag,
  one CHANGELOG.
- **Migration:** three stacked PRs into `scope/v0.3.0`: `chore/pnpm-turborepo` (app still at the
  root) → `chore/apps-mobile` (move, reinstall on device) → `feat/web-landing` (shared packages,
  Next.js, Vercel).

Still open: the web domain.
