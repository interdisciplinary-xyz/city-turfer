## Monorepo design

Full record: `docs/decisions/monorepo-turborepo-2026-10-18.md`. Decided:

- **Landing page goal:** static showcase only (what CityTurfer is, how turf works, screenshots,
  "coming soon"). No data collection, so no backend and no GDPR surface.
- **Web stack:** Next.js on Vercel. Static pages now; a waitlist or API routes can come later.
- **Package manager:** pnpm (replaces npm 10 + `legacy-peer-deps`).
- **Shared packages from day one:** `packages/brand` (colour tokens including the turf strength
  ramp, SVG mark and wordmark, tagline copy) and `packages/config` (tsconfig, ESLint, Prettier
  bases).

- **Layout:** `apps/mobile` takes the app with its Maestro flows and the mobile-only tools;
  repo-wide tools (docs audit, secret guard, log audit, release) and `docs/` stay at the root. One
  version, one tag, one CHANGELOG.
- **Migration:** three stacked PRs into `scope/v0.3.0`: `chore/pnpm-turborepo` (app still at the
  root) → `chore/apps-mobile` (move, reinstall on device) → `feat/web-landing` (shared packages,
  Next.js, Vercel).

Still open: the web domain.

## Monorepo migration

**[1/3] #48 `chore/pnpm-turborepo`** (merged 2026-10-18)

- pnpm 10.22.0 pinned in `packageManager`; `pnpm-lock.yaml` imported from `package-lock.json`, so
  versions are unchanged. `.npmrc`: `node-linker=hoisted`, `auto-install-peers=false`,
  `strict-peer-dependencies=false`. Install scripts allowed for `better-sqlite3` and
  `unrs-resolver`.
- Turborepo runs `typecheck`, `arch`, `test:unit` (cached); CI and Release workflows use pnpm.
- **Problem found:** with `auto-install-peers=true` pnpm installed peers npm never did (Reanimated,
  Worklets, Gesture Handler) and CocoaPods autolinked them. `auto-install-peers=false` (the real
  equivalent of `legacy-peer-deps`) restores the npm build's pods exactly.
- **Runtime fingerprint already changes here** (hoisted autolinking paths, `package.json` scripts),
  not only in [2/3]: no OTA until the reinstall after [2/3].
- Verified: 281 Jest tests, `pod install` matches npm, fresh dev build, Maestro 10/10, CI green.

**[2/3] #49 `chore/apps-mobile`** (merged 2026-10-18)

- The app moves to `apps/mobile` (`@cityturfer/mobile`) with its Maestro flows, native module,
  plugins and the mobile tools; repo-wide tools stay in `tools/`. Same 1,278 resolved packages,
  hoisted to the root.
- `apps/mobile/app.json` pinned to 0.3.0; `.versionrc.json` bumps root, app `package.json` and
  `app.json` together.
- `ios/` regenerated with `expo prebuild --clean` in `apps/mobile`: same pods as [1/3].
- Verified: 281 Jest tests, 26 tool tests, dependency rules, dev build from `apps/mobile`, Maestro
  10/10, OTA bundle export (1,339 modules). New runtime fingerprint `30e78edb…`.

**[3/3] #50 `feat/web-landing`** (merged 2026-10-18)

- `packages/config` (`@cityturfer/config`): Prettier config (was `.prettierrc.json`) and tsconfig

  fingerprint stopped moving with script edits (`fb9fc2e8…` at #50; see the correction under #52).
- **Vercel:** creating the project through the Vercel integration was refused (403), so it is a
  founder action: project `city-turfer-web`, root directory `apps/web`, framework Next.js.

## Follow-ups after the local review

**#51 `feat/web-hero-screens`** (merged 2026-10-18)

  side under the copy on phones); the separate "In the app" section is gone.

**#52 `chore/eslint-config`** (merged 2026-10-18)

- `packages/eslint-config` (`@interdisciplinary/eslint-config`) copied from empatalk-app: presets
  `base`, `react`, `package`, the `local-rules` plugin and its vitest tests. Each app keeps its
  specifics (Next.js for web, react-native-a11y for mobile); packages use `package`.
- Code brought in line: `curly: all` (319 autofixes), types and constants moved to colocated
  `*.constants.ts`. Expo Router screens are exempt (every file in `apps/mobile/src/app` becomes a
  route).
- **Problem found:** the pre-commit hook lints several workspaces in one run and typescript-eslint
  could not pick a tsconfig root; every config now sets `tsconfigRootDir`.
- Maestro 10/10 after the autofix.
- **Correction (found while starting v0.4.0):** the autofix also added braces in
  `apps/mobile/plugins/with-scene-lifecycle.js`, an Expo config plugin, and plugin files are part of
  the runtime fingerprint. Behaviour is unchanged, but the v0.3.0 runtime is **`88392eb0…`**, not
  `fb9fc2e8…` as #56 first said. Nothing had been installed or published in between.

**#53 `feat/dev-toolbar`** (merged 2026-10-18)

- `packages/dev-toolbar` (`@interdisciplinary/dev-toolbar`) copied from empatalk-app: the dev-only
  bottom toolbar with live request log and route map. Typechecks against Next 16 / React 19.2
  unchanged; its 59 vitest tests pass.
- `apps/web/server.mjs`: dev-only custom server that wraps Next with the toolbar's Node half (marks
  requests from this machine, serves `/__dev/*`). `pnpm run web:dev` runs it through portless.
- The layout renders the toolbar only in development and only for this machine (phones on the LAN
  URL never see it); the adapter `apps/web/src/app/dev-toolbar-with-app/` passes our props.
- Tailwind v3 styles only the toolbar: content is the toolbar package, preflight is off, and its CSS
  is imported from the dev-only adapter. A scoped reset gives the toolbar's controls what preflight
  would have.
- `output: 'export'` applies to production builds only (in development the page renders per
  request). The production export was checked: no toolbar code, text or CSS.
- `sitemap.xml` added (the route map reads it; useful for search anyway). Its origin comes from
  `NEXT_PUBLIC_SITE_URL`, else Vercel's production URL.
- `apps/web/AGENTS.md` is Prettier-ignored: `next dev` rewrites it unwrapped, so a wrapped copy
  always showed as changed.

**#54 `feat/web-i18n`** (merged 2026-10-18)

- The landing page keeps only its first section (hero with the two phones); "How turf works",
  privacy and the footer are gone.
- **Languages: English and Polish** with `next-intl` 4, no CMS: copy in `apps/web/messages/en.json`
  and `pl.json`, routing in `apps/web/src/i18n/`. Every language is a URL prefix (`/en`, `/pl`),
  prerendered by the static export.
- `/` has no content: `vercel.json` redirects Polish browsers to `/pl` and everyone else to `/en`;
  the exported `index.html` also redirects (meta refresh) for other hosts and no-JS visitors.
- EN / PL switch at the top right (and in the dev toolbar's slot). Each page has `<html lang>`, a
  canonical URL and `hreflang` alternates; the sitemap lists both languages.
- **Problem found:** next-intl 4's `Link` is a client component and needs `NextIntlClientProvider`;
  without it the build failed with an empty prerender error. The provider wraps the page and the dev
  toolbar.
- The app screenshots stay English (the app is English-only).
