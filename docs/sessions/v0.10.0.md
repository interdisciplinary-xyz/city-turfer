### Account settings (#142)

- **API 0.5.0 (additive):**
  - `PATCH /v1/me` changes the name.
  - Step-up codes go to the current address and are limited per account, so a stranger can't block
    them.
  - Email change (one address rule shared with sign-in).
  - `PUT` / `DELETE /v1/me/password`.
  - `{ email, password }` on `POST /v1/auth/sign-in`.
  - Email and password changes, and removing the password, sign out every other session.
  - Breached passwords are refused through the HIBP range API, which fails open.
  - No migration.
- **Phone (JS only):** Me › Account rows and flows for name, email and account password; "Use a
  password instead" on sign-in. The name replaces the user id on Profile and Home.
- **E2E:** Maestro flow `15-account-settings` (tag `account`, needs the local API with
  `AUTH_FIXED_CODE`; `run.sh` skips it when the API is down).
- **Reviewed twice**, by mobile-reviewer and then a four-lane team review (19 threads, all fixed and
  resolved). At merge: API 154 tests, core 167, mobile 435.
- **Not run:** the screens and flow 15 on a simulator or device, real HIBP calls from Vercel, Brevo
  delivery of the six new mails.

### Web portal Slice 0 (#141)

Founder decisions 2026-10-22 (`docs/decisions/web-portal-2026-10-22.md`): keep the static export,
Slice 0 first, pages under `/[locale]/account`, web sessions 14 days sliding / 30 days absolute / 8
hours on a shared computer.

- **API (contract 0.5.0, combined with #142):**
  - Browser sign-in by code or password sets `__Host-ct_session`
    (`Path=/; HttpOnly; Secure; SameSite=Strict`); no token in the body
    (`docs/decisions/api-web-sessions-2026-10-22.md`).
  - Cookie writes need `Origin` = `WEB_ORIGIN` and `CityTurfer-Client: web/<version>`, else 403
    `auth.csrf`; phones (bearer) are unaffected.
  - Signed-in devices: list, sign out one, others, or everywhere (phones included), in SQL with no
    row cap. Migration 0004 (`auth_sessions.client`, `absolute_expires_at`).
  - Client IP: `x-vercel-forwarded-for` is trusted only behind the website's `cityturfer-edge`
    secret (`WEB_EDGE_SECRET`); direct callers get the last `x-forwarded-for` entry.
- **Website:** sign-in and Privacy & data (consents read-only, export, delete account, devices) as
  static pages fetching through a typed client; `/api/v1/*` routed to the API in `vercel.json` with
  per-route security headers. Public pages stay cookie- and API-free, enforced by a dependency rule
  and a post-build check.
- **Tests:** API 211, web 49 node + 118 vitest, Playwright portal E2E 12/12
  (`pnpm --filter @cityturfer/web run test:e2e`, not in CI yet).
- **Reviewed** by a six-lane team review: 39 threads, all fixed or answered and resolved. The new
  tests found two bugs (a malformed cookie answered 503; empty strings stored for IP and user
  agent), both fixed.
- **Not run:** a Vercel preview pair (cookie and client IP through the route, edge caching), Safari,
  real Brevo mail, the phone after "sign out everywhere".

### Server turf (#149)

Founder decision 2026-10-23: build it in v0.10.0 for the web map (Slice 1); checkpoint 2026-10-27,
met on 2026-10-23. Design: `docs/decisions/api-server-turf-2026-10-23.md`.

- **API (contract 0.6.0):**
  - Migration 0005: `turf_claims`, `turf_cells` (counts per type and the canonical first claimer,
    `COLLATE "C"`), `users.turf_version`. No coordinates stored; erasure by cascade.
  - Turf changes in the same locked transaction as the backup change (upload, replace, delete,
    backup off, Apple Health off, account deletion). A start in the future is left unclaimed and
    caught up by the daily cron.
  - `GET /v1/turf/cells` (pages, ETag, `410 turf.changed`, `private, no-store`); `/v1/turf/summary`
    and `/v1/turf/claims/{id}` live; `GET /v1/activity-totals`; date filters on the activity list.
  - `turf:backfill` (idempotent, budgeted) and `turf:rebuild` (after a rollback).
- **Core:** `createTurfApi`, `ListTurfCells`, strength exports for the web; a parity golden checked
  in core, on the phone (real SQL) and through the API (C and ICU collation).
- **Phone (JS only):** `releaseClaim` recomputes `first_at` after a delete. Known gap, pinned by a
  test: the phone's "new cells" of a late Apple Health walk differ from the server's canonical ones;
  the web takes "new turf" from the server.
- **Tests at merge:** API 266, core 220, mobile 438. Reviewed by mobile-reviewer (no blockers; its 4
  should-fix items fixed before the PR).
- **Not run:** Neon (array binding, locks, collation, latency), Vercel (cold start with the h3
  bundle, the cron's 60 s, a 50k-cell download), a Hermes release build on a device.
