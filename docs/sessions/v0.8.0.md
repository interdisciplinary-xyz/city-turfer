## Decisions (founder, 2026-10-20)

**Turf on the Record map**, as a toggle:

- **Shown by default.** It makes it obvious where new streets are.
- **Remembered** per user on the phone.
- **Available before and during a recording.** It helps steer toward streets not covered yet.

**An HTTP API for the app** (`docs/decisions/api-2026-10-20.md`), in five phases, each a PR into the
scope; mobile stays JS-identical and OTA-safe until phase 5:

1. Tooling (skill, agent, spec generation) — #89
2. `apps/api` skeleton, every route declared — #90
3. packages/core (`@cityturfer/core`, planned): domain + application layers out of the app
4. Routes on Neon Postgres (Frankfurt) + Drizzle, auth (Better Auth later)
5. Mobile sync client; upload of the existing `admin` history

Hono on Vercel (`fra1`), contract-first with zod 4 → OpenAPI 3.1; the server recomputes turf from
uploaded tracks; activities carry an IANA time zone; EU regions only.

**A Product Owner persona** (`product-manager` agent) accountable for product outcomes, owning
`docs/product/`, backed by desk research on product practice, the market and store/privacy rules.

### `feat/record-turf-overlay` — turf on the Record map (PR into scope)

- **UI:**
  - The "⬡ Turf" chip (`record-turf`, `accessibilityRole` switch) sits top right on the Record map,
    in one column with Recenter below it. The chip is filled pink when on, card-coloured when off,
    with a hit slop for a 44 pt target.
  - The Turfer's turf draws under the live track: the Turf Map's heatmap glow and strength-coloured
    hexagons in a lighter `overlay` look (`TURF_LOOK`), so streets stay readable.
- **Boundary:** Recording still never imports Territory. The Record screen
  (`apps/mobile/src/app/(tabs)/record.tsx`) composes:
  - `useTurfOverlay()` (`territory/ui/hooks.ts`)
  - `<TurfLayers beforeId={LIVE_TRACK_BOTTOM_LAYER} look='overlay'>` passed as `RecordView`'s
    `mapOverlay`
  - `onViewChange` from the map's region events
- **Preference:** `turf-overlay-preference.ts` in Territory's infrastructure (secure store, per-user
  key). Unset or unreadable means shown; writes are best effort.
- **Cost while recording:**
  - Turf is loaded for the view grown by half its size on each side, 4× the area, about 4.8× with
    the query's own padding (`turf-overlay-area.ts` in Territory's ui).
  - It is re-read only when the view leaves that area or crosses `DETAIL_ZOOM`.
  - The view lives in a ref, so following the Turfer re-renders nothing.
  - `TurfLayers` is memoised.
- **Review (mobile-reviewer) before the first commit:**
  - **Must-fix, layer order:** MapLibre adds layers on top of the style whatever their JSX position,
    so turf covered the live track and the location dot. Fixed with `beforeId`, the overlay always
    mounted after the live track (empty when hidden), and `UserLocation` last.
  - **Must-fix, cell budget:** a 9× load area could pass `GetTurfInViewport`'s 5000-cell budget, and
    hexagons then vanish at street zoom. The margin is now 0.5 (4×).
  - **Should-fix:**
    - per-fix re-render and GeoJSON re-serialisation (ref plus `memo`)
    - region events can be sparse while following (now both `onRegionIsChanging` and
      `onRegionDidChange`)
    - the e2e flow depended on the previous run's state (now normalised)
  - **Nits:** Recenter jumping once (the default is shown while loading), hit slop, and the previous
    Turfer's choice flashing after an account switch.
- **"The toggle doesn't switch" was the test environment (2026-10-20):**
  - Expo's floating "Tools" button, which only dev builds have, sits top right, exactly over the
    chip, and swallowed Maestro's taps.
  - `apps/mobile/e2e/run.sh` now switches off the dev menu's auto-open and the floating button on
    the Simulator before each run.
  - On a dev build on the iPhone, drag the button aside or switch it off in the dev menu; release
    builds don't have it.
  - The same pause fixed `12-home-city`, which asserted chip text that iOS exposes only as
    accessibility labels.
- **Second review (mobile-reviewer, new instructions from #91):** nothing blocking. Fixed:
  - chips in one column: no overlap at large text sizes or overlapping hit slop
  - the dev-menu preferences written into the app's own preferences file too
  - a stricter Home City assertion
  - the 4.8× wording
- **Tests:**
  - Jest: area rule (6), preference (3)
  - Maestro `13-record-turf` (CP-11): default on, hide, remembered across a restart, toggled during
    a recording
- **Docs:** `turf-territory` skill, `docs/engineering/features.md`, `docs/quality/e2e.md`.
