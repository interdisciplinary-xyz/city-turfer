# Mobile app in English and Polish

Launch readiness item 17 (`docs/product/launch-readiness.md`): the website is EN/PL and redirects
Polish browsers to `/pl`, the app is English-only, and the first market is Polish cities
(`docs/product/strategy.md`). This record holds the decisions and the plan, executed on
`feat/mobile-i18n` → `scope/v0.10.0`.

## Starting point (inventory, 2026-10-23)

- About 500 literal strings in `apps/mobile/src` (≈ 200 already in `*.constants.ts`, ≈ 300 inline
  JSX, `Alert.alert` and accessibility labels) and about 100 in shared code: `packages/brand`
  (`TAGLINE`, `TIER_LABEL`, …), `packages/core` (12 achievements, 5 onboarding steps, the default
  activity name, 38 city names), `packages/ui` (`TurfLegend` defaults and its accessibility text).
- Plurals are English ternaries (`n === 1 ? … : …`); Polish needs one / few / many / other.
- `format.ts` writes decimals with `toFixed` (`2.50 km`; Polish writes `2,50 km`) and dates with the
  phone's locale, not the app's. Cloud backup hand-rolls "5 min ago" and English month names.
- The Android recording notification is built in JS (`expo-location-tracker.ts`): translatable
  without native work. iOS permission prompts (`app.json` plugins) are native strings.
- No i18n library in the app. `use-intl` 4.14.9 and `intl-messageformat` are already installed (the
  website's `next-intl`). `expo-localization` is not installed.
- Jest renders nothing (node environment): copy is asserted through constants and format functions
  in about 10 files. 12 of 15 Maestro flows match English text.

## Decisions

| #   | Decision               | Outcome                                                                                                                                                                                                                                                                                                                                                            |
| --- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| L1  | Languages              | **English (`en`, default and fallback) and Polish (`pl`)**, the website's pair. Adding one later = a folder of JSON files and one entry in `LOCALES`.                                                                                                                                                                                                              |
| L2  | Library                | **`use-intl`** (pinned to the website's version): ICU messages (`{count, plural, one {…} few {…} many {…} other {…}}`), `useTranslations` in components and `createTranslator` outside React (alerts built in handlers, the recording notification). Same message syntax and terms as `apps/web/messages`, so copy can move between them.                          |
| L3  | Plural rules on Hermes | ICU plurals need `Intl.PluralRules`; Hermes has not always shipped it. **`@formatjs/intl-pluralrules`** (pure JS) is loaded only when `shouldPolyfill()` says so, with `en` and `pl` data. Verified on a simulator before the PR is called done.                                                                                                                   |
| L4  | Which language         | An in-app **Language** setting (System · English · Polski) in Info, stored device-wide in the secure store (it applies before sign-in). **System** = the phone's language from `Intl.DateTimeFormat().resolvedOptions().locale` (JS, no native module), `pl*` → Polish, anything else → English. A change applies at once, no restart.                             |
| L5  | Catalogue layout       | `apps/mobile/messages/<locale>/<namespace>.json`, one namespace per area (`common`, `record`, `turf`, `history`, `stats`, `achievements`, `account`, `backup`, `health`, `info`, `signIn`, `errors`, …): small files, one owner each, parallel work without merge conflicts. Keys are camelCase, English is the source.                                            |
| L6  | Numbers, dates, units  | `format.ts` formats with the **app** locale (`Intl.NumberFormat` / `DateTimeFormat`): `2,50 km` and `5:12 /km` in Polish. Units stay metric and unlocalised symbols (`km`, `km/h`, `km²`). `formatArea` keeps its deliberate grouping-free output. Counts inside messages are grouped by ICU ("1,234 workouts"), except where a test matches the text (`fixed()`). |
| L7  | Stored text            | The **default activity name** is created in the language active at the time (core takes the words as a parameter; core stays free of i18n). Existing names are user data and are never rewritten. Achievement and onboarding text is looked up by id in the catalogue; core keeps its English text as the fallback for the API.                                    |
| L8  | City names             | Polish names (Warszawa, Praga, Wiedeń, …) by city id in the catalogue; search matches both the English and the Polish name.                                                                                                                                                                                                                                        |
| L9  | Ubiquitous language    | Code keeps the domain terms (`cycle`, `Claim`, `Turf Cell`); only the catalogue translates. Polish terms follow the website: "turf" stays (inflected: "Twój turf", "Mapa turfu"), cells = "komórki", spacer / bieg / rower.                                                                                                                                        |
| L10 | Native strings         | **Not in this branch.** iOS permission prompts and `CFBundleLocalizations` (per-app language in iOS Settings) and Android `locales_config` change the runtime fingerprint (new binary, not over the air). They follow in a later binary release with `expo-localization` and `expo.locales` (open item in launch readiness).                                       |
| L11 | Enforcement            | `pnpm run audit:i18n` (in `ci:quality`): every locale has the same keys, every message parses as ICU, placeholders match across locales, Polish plurals carry `one`, `few`, `many` and `other`. A lint rule refuses raw text in `apps/mobile` JSX and in user-facing props and `Alert.alert` (dev-only screens exempt).                                            |
| L12 | Tests                  | Unit tests for the locale resolution, the translator and `format.ts` in both locales; the catalogue audit; the existing Maestro flows keep running in English (simulators default to English) and one new flow switches to Polski and checks a few screens.                                                                                                        |

Rejected: i18next (its own plural JSON, a second message dialect next to the website's ICU);
`expo-localization` now (native module: fingerprint change for one locale string we can read from
`Intl`); one big JSON per locale (every agent editing one file); translating stored names after the
fact (user data); keeping `TIER_LABEL` and other `@cityturfer/brand` copy as the app's source (the
catalogue owns app copy; brand keeps the English names for the website's branding page and
Storybook).

## Plan

Each step names its owner (the `add-feature` skill's ownership map) and ends green on
`pnpm run ci:quality`.

0. **Harness** (`harness-engineer`): the `mobile-i18n` skill (how to add, name, pluralise and test a
   string; the Polish glossary; what is not translated); `tools/i18n-audit.mjs` +
   `tools/__tests__/i18n-audit.test.mjs` + `audit:i18n` in `ci:quality` (website messages checked
   too); the no-raw-text lint rule in `@interdisciplinary/eslint-config` (opt-in) switched on for
   `apps/mobile` after the migration; ownership lines in the `add-feature` skill and the
   `mobile-ui-engineer` and `brand-designer` agents; `CLAUDE.md` lines.
1. **Foundation** (`mobile-ui-engineer`): `apps/mobile/src/i18n/` (locales, resolution, provider,
   `useT`, `translator()` for non-React code, the plural polyfill guard), the Language setting and
   its row in Info, `format.ts` on the app locale, the `common` namespace. Pinned `use-intl`.
2. **Copy migration** (`mobile-ui-engineer`, by area): screens and context `ui/` move every string
   to their namespace, plurals become ICU, composed strings become whole messages (no
   `TYPE_LABEL.toLowerCase()` splicing). Error codes map to messages; raw `Error.message` is never
   shown. Includes the Android recording notification (`location-engineer` reviews the
   infrastructure change) and `packages/ui` accessibility text via props.
3. **Core inputs** (`location-engineer`): `defaultName` takes the words; app passes them from the
   catalogue at creation. City search over localised names.
4. **Polish** (`brand-designer`): every Polish message reviewed for natural Polish and the glossary,
   plurals in all four forms, length checked on small screens.
5. **Verify** (`mobile-test-engineer`): unit tests, the new Maestro language flow, a simulator run
   in both languages (Intl and plural rules on Hermes), the runtime fingerprint unchanged
   (`pnpm -C apps/mobile exec expo-updates fingerprint:generate`).
6. **Docs**: this record → `canonical`, `docs/engineering/features.md`, launch readiness item 17
   (in-app done; native prompts open).

## Executed (2026-10-23)

All steps ran on `feat/mobile-i18n`: 22 namespaces in English and Polish, the Language card in Info,
`audit:i18n` and `local-rules/no-raw-text` on in `ci:quality`, Maestro flow `16-language` (CP-13).
Checked on the iPhone 17 Pro simulator: the English regression suite, every screen in Polish, Hermes
plurals (one / few / many). The runtime fingerprint is unchanged on both platforms, so it ships over
the air.

The Language setting is stored readable after first unlock (a recording started from a locked phone
still builds the Android notification text in the chosen language). An unreadable keychain falls
back to the phone's language and is read again when the app comes to the front; the launch spinner
waits at most `LANGUAGE_READ_TIMEOUT_MS` for it.

Not verified: the Polish Android recording notification on a device (the emulator showed no
notification at all, also in English), the Maestro suite on Android, `15-account-settings` (fails at
`hideKeyboard` on the iOS 26.1 numeric keypad, unrelated to language).
