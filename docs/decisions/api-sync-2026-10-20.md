# Sync-first API contract (v0.8.0)

The founder asked for "a step back in API design" on 2026-10-20. The api-engineer reviewed the first
skeleton (`docs/decisions/api-2026-10-20.md`) from the domain out; the founder accepted every
recommendation (D1–D13 below) the same day. This record supersedes that document's **v1 routes**
table and the parts named in "What changed"; its stack, phases and hosting choices still stand. How
to work on it: the `api-design` skill. Code wins on conflict: the generated `apps/api/openapi.json`
is the contract.

## Why a step back

The first skeleton mirrored the app's screens (list, detail, rename, turf views). For a long time
the only client is the phone, which is local-first: it records and owns its data and needs to **back
it up and sync it**, not to read screens from a server. Missing for that: a changes feed, explicit
deletes (tombstones), versions and preconditions for track corrections (`SplitTrackGaps` →
`ActivityTrackCorrected`), and an upload body that carries what the domain needs (`resumedSegments`,
a required `name`, `source`).

## What changed

- **Sync:** new `GET /v1/sync/changes` — upserts, tombstones and the Home City since an opaque
  cursor; cursor-less it is the manifest for a first upload.
- **Activity Log:** `PUT /v1/activities/{activityId}` uses preconditions (`If-Match`, 412/428),
  answers **410 `activity.deleted`** for a deleted id (delete wins, no undelete); Activities carry
  `version`, `trackHash` and an `ETag`; paging is an opaque `cursor`; names are 1–80 characters like
  `Activity.rename`; new `PUT …/gap-routes` (the phone's street estimates, display only).
- **Track points** are `[lon, lat, t, segment, altitudeM | null]`: accuracy and speed are no longer
  sent (D1).
- **Territory:** the claim moved to `/v1/turf/claims/{activityId}`, the Home City to
  `/v1/turf/home-city` (Territory owns both; the token is the tenant); clearing it is `PUT` with
  `cityId: null` (last write wins on `chosenAt`). Removed: `DELETE /v1/me/home-city`,
  `GET /v1/achievements` (local-time rules, nothing stored — evaluated on the device),
  `GET /v1/cities` (the catalogue ships with the app; back with a web client).
- **Privacy:** `GET /v1/me/export` became an async export (`POST /v1/me/exports`,
  `GET /v1/me/exports/{exportId}`) because Vercel caps **responses** at 4.5 MB as well;
  `DELETE /v1/me` answers 202 (an erasure job); new consents (`GET /v1/me/consents`,
  `PUT /v1/me/consents/{purpose}`).
- **Identity:** `POST /v1/auth/sign-in` is the mock, marked dev-only; Better Auth brings its own
  endpoints later.
- **Platform:** requests to protected routes are authenticated **before** they are validated (401
  before 400); every answer carries `X-Request-Id`; `GET /v1/health` reports `coreVersion`.

## Contract 0.4.0 (2026-10-22)

Founder decisions of 2026-10-22: opt-in backup, real accounts, restore to a new phone, rename,
export and account deletion. What changed in the contract:

- **Changes feed:** activity entries carry
  `id, type, source, name, startedAt, version, trackHash, updatedAt` and no `preview` or numbers; a
  page ends at `limit` changes or about 1 MB. **Restore** = the feed from no cursor (the manifest),
  then `GET /v1/activities/{id}` and `…/track` per activity.
- **Gap routes:** `ActivityDetail.gapsCheckedAt` is set by `PUT …/gap-routes`; an empty list means
  "checked, no gaps", so a restored phone does not ask the router again. A new track clears it.
- **Source:** derived from the id — `hk-…` is `apple-health` and only it is; a mismatching `source`
  answers 422 `activity.source-mismatch` (the Apple Health consent cannot be skipped by a label).
- **Rename:** `PATCH /v1/activities/{id}` `{ name, renamedAt }` is live and answers the
  `ActivityDetail` (now with `renamedAt`); last write wins on `renamedAt` (equal or older → 200,
  unchanged); 422 `activity.invalid-name` from the core rule; `If-Match` optional (412 when stale).
  Migration `0001_activity_renamed_at`.
- **Platform:** `GET /v1/health` reports `coreVersion`; a 400 lists at most 20 `errors[]`.
  `claim.in-future` left the catalogue (the server claims no turf yet).

## Sync protocol

**Principles.** The phone is authoritative for what it recorded. Every write is keyed by an id the
phone minted and is replay-safe (PUT, PATCH and DELETE are idempotent by construction, so there is
no `Idempotency-Key`). Deletes are tombstones, never inferred from absence. One per-user,
monotonically increasing change sequence orders the feed; the cursor is opaque.

**Server state per Activity:** `version` (+1 on every change; `ETag: "v<version>"`), `trackHash`
(SHA-256 of the canonical track, computed by the phone, checked by the server → 422
`activity.track-hash-mismatch`), `updatedAt`, a tombstone `deletedAt`.

**Phone side (later, needs its own go):** a `sync_state` table and an `ActivityRenamed` event; the
sync client is an outbox consumer: `ActivityRecorded` → PUT, `ActivityTrackCorrected` → PUT with
`If-Match`, `ActivityRenamed` → PATCH, `ActivityDeleted` → DELETE, `ActivityDistanceEstimated` → PUT
gap-routes, `HomeCityChosen` → PUT home city. Offline only means "pending" (outbox backoff).

### First upload of the existing `admin` history

1. **Account and consent.** Dev and preview servers seed the mock `admin` account; production never
   does (D8). A real first sign-in on a phone with local data asks "Back up N activities from this
   phone?" → `PUT /v1/me/consents/cloud-sync`; Apple Health imports need
   `PUT /v1/me/consents/apple-health-in-cloud-sync` too (D2).
2. **Manifest:** `GET /v1/sync/changes` without a cursor, every page. New account: empty.
3. **Plan** per local Activity (never `demo-*`; `hk-*` only with the Health consent): absent →
   upload; same `trackHash` → synced; different hash → upload with `If-Match`; tombstoned → delete
   locally.
4. **Upload** oldest first, two at a time, gzip; then the gap routes. Resumable: a replay of the
   request in flight answers 200.
5. `PUT /v1/turf/home-city` with the local `chosenAt`.
6. Keep the last `nextCursor`; from then on pulls are incremental.

Existing activities have no time zone: the phone sends its current zone.

### Steady state and a second device

- **Push** from the outbox when online; recording never waits for the network.
- **Pull** on launch, foreground and after pushing: for each change, fetch the track when its
  `trackHash` is new (`GET …/track`, `If-None-Match`), import or correct it locally (no echo back),
  apply renames, delete tombstoned activities, apply a newer Home City. Territory claims synced
  activities as usual, so turf is rebuilt on the device.
- **Apple Health on two phones:** imported ids are stable (`hk-<uuid>`), so the same workout is one
  Activity. **Pull before importing from Health**, so the same-outing check sees the other phone's
  recording. A deleted `hk-` activity answers 410 on upload; the phone records its link so it
  doesn't import it again.

### Conflicts

| Case                                   | Rule                                                     |
| -------------------------------------- | -------------------------------------------------------- |
| Same id, same content                  | 200, unchanged (replay)                                  |
| Track corrected on the recording phone | `PUT` with `If-Match` → 200, version + 1                 |
| Stale `If-Match`                       | 412 with the current `ETag`; pull, re-apply, retry once  |
| Different content without `If-Match`   | 428 `precondition-required`                              |
| `PUT` on a deleted id                  | 410 `activity.deleted`; delete locally — **delete wins** |
| Renames on two devices                 | last write wins (`If-Match` optional)                    |
| Home City on two phones offline        | last write wins on `chosenAt`                            |
| Cursor no longer valid                 | 410 `sync.cursor-expired` → start again without a cursor |

## Errors

`application/problem+json` (RFC 9457) with a stable `code`; invalid input lists JSON pointers in
`errors[]` (at most 20), never values. Catalogue: `invalid-request` 400 · `auth.missing`,
`auth.invalid` 401 · `not-found` 404 · `activity.deleted`, `sync.cursor-expired` 410 ·
`precondition-failed` 412 · `payload-too-large` 413 · `unsupported-media-type` 415 ·
`activity.track-too-short`, `activity.ends-before-start`, `activity.invalid-name`,
`activity.track-hash-mismatch`, `activity.source-mismatch`, `home-city.unknown` 422 ·
`client.too-old` 426 · `precondition-required` 428 · `rate-limited` 429 · `internal` 500 ·
`not-implemented` 501. Defined once in `apps/api/src/errors.ts`.

## Headers

`Authorization: Bearer`, `ETag`, `If-Match`, `If-None-Match`, `Content-Encoding: gzip` (uploads,
inflated with a size cap), `CityTurfer-Client` (e.g. `ios/0.8.0+123`; 426 when too old),
`X-Request-Id`, `Retry-After`, `RateLimit` / `RateLimit-Policy`, `Location` on 201 and 202.
Versioning: `/v1` for breaking changes, `info.version` (semver) for additive ones,
`Deprecation`/`Sunset` before a removal.

## Privacy

GPS tracks, cells and the Home City are personal data. Cloud sync is opt-in with a recorded consent
(policy version). Export covers every table, tombstones and consents included; files expire after 24
h. Erasure revokes sessions at once and deletes rows, then stored files; data survives in database
backups for the provider's restore window (to be stated with the Neon plan). Tombstones keep only
`(user, id, deletedAt)`. Logs carry route, status, duration, request id and user id — never bodies,
coordinates, cells or tokens. Spec examples use public landmarks only (a test checks it).
